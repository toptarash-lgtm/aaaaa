============================================================
  استقرار پنل لایسنس Batman روی Railway
============================================================

این نسخه برای Railway آماده شده است:
  • ذخیره داده روی Volume در مسیر /data
  • ساخت ادمین از Environment Variables
  • Healthcheck روی /api/health
  • پشتیبانی HTTPS (کوکی Secure)
  • HMAC از env یا فایل

────────────────────────────────────────
مرحله ۱: حساب Railway
────────────────────────────────────────
1. برو به: https://railway.app
2. با GitHub وارد شو (پیشنهادی) یا ایمیل
3. یک پروژه جدید بساز: New Project


────────────────────────────────────────
مرحله ۲: آپلود کد
────────────────────────────────────────
فقط پوشه license-panel را آپلود/دیپلوی کن (نه کل zip).

روش A — از GitHub (پیشنهادی):
  1. یک ریپوی خالی در GitHub بساز
  2. محتویات پوشه license-panel را داخل آن push کن
     (server.js, package.json, public/, lib/, cli.js, railway.toml)
  3. در Railway: New Project → Deploy from GitHub repo → همان ریپو

روش B — Railway CLI:
  npm i -g @railway/cli
  railway login
  cd license-panel
  railway init
  railway up


────────────────────────────────────────
مرحله ۳: Volume پایدار (خیلی مهم)
────────────────────────────────────────
بدون Volume بعد از هر redeploy لایسنس‌ها پاک می‌شوند.

در داشبورد Railway روی سرویس:
  Settings → Volumes → Add Volume
  Mount Path:  /data
  (اندازه ۱GB کافی است)

در Variables این را هم بگذار (اختیاری ولی واضح‌تر):
  DATA_DIR=/data

کد در محیط Railway اگر DATA_DIR نباشد خودش /data را استفاده می‌کند؛
ولی حتماً Volume را روی /data مانت کن.


────────────────────────────────────────
مرحله ۴: متغیرهای محیطی (Variables)
────────────────────────────────────────
در Settings → Variables این‌ها را اضافه کن:

  ADMIN_USERNAME = admin
  ADMIN_PASSWORD = یک_رمز_قوی_حداقل_۸_کاراکتر

اختیاری ولی توصیه‌شده:
  HMAC_SECRET = یک_رشته_تصادفی_حداقل_۳۲_کاراکتر
  (مثلاً خروجی: openssl rand -hex 32)

اگر HMAC_SECRET نگذاری، سرور یک‌بار می‌سازد و در /data ذخیره می‌کند
(با Volume پایدار می‌ماند).

PORT را دست نزن؛ Railway خودش می‌گذارد.


────────────────────────────────────────
مرحله ۵: دامنه عمومی
────────────────────────────────────────
Settings → Networking → Generate Domain
یک آدرس مثل:
  https://batman-license-xxxx.up.railway.app
گرفته می‌شود.

می‌توانی دامنه اختصاصی هم وصل کنی.


────────────────────────────────────────
مرحله ۶: تست
────────────────────────────────────────
1. باز کن: https://YOUR-DOMAIN.up.railway.app
2. با ADMIN_USERNAME / ADMIN_PASSWORD وارد شو
3. چک سلامت: https://YOUR-DOMAIN.up.railway.app/api/health
   باید {"ok":true,...} برگردد


────────────────────────────────────────
مرحله ۷: اتصال پنل VPN مشتری
────────────────────────────────────────
روی سرور VPN مشتری، آدرس لایسنس را به دامنه Railway بگذار:

  LICENSE_SERVER_URL=https://YOUR-DOMAIN.up.railway.app

(بدون اسلش آخر، با https)

در کانفیگ پنل VPN (env یا فایل config) همین را ست کن.
WebSocket هم روی همان دامنه کار می‌کند (wss://...).


────────────────────────────────────────
نکات مهم
────────────────────────────────────────
• حتماً Volume روی /data داشته باش وگرنه دیتای لایسنس بعد از deploy از بین می‌رود
• HMAC_SECRET را عوض نکن بعد از صدور لایسنس (کلیدهای قبلی نامعتبر می‌شوند)
• سشن ادمین در حافظه است؛ با restart همه از پنل خارج می‌شوند (لایسنس‌ها در فایل می‌مانند)
• پلن رایگان Railway محدودیت خواب (sleep) دارد؛ برای پنل لایسنس بهتر است پلن پولی کوچک
  یا سرویس همیشه روشن باشد تا validate و WebSocket قطع نشوند
• لاگ‌ها: در Railway → Deployments → View Logs


────────────────────────────────────────
دستورات مفید CLI
────────────────────────────────────────
  railway logs
  railway variables
  railway open
  railway up


اگر Volume یا env را درست ست کنی، باگ خاصی از سمت Railway برای این کد
وجود ندارد؛ همان منطق VPS کار می‌کند.
